# 支线方案：多一块 ESP32-S3 的使用策略（v1.0，2026-10-29）

> 前提：主线 = 收发一体 4 节点 12 链路（已推送 GitHub，`v0.1-baseline` 为验收保底）。
> 本文回答"如果多一块 S3 怎么用最优"，并把每条路线的**提前准备**写到可执行精度。
> 原则：主线真机联调完成前，不改任何主线代码；支线全部以文档预案 + 增量分支形式准备。

---

## 1. 结论：三档角色，按优先级启用

| 优先级 | 角色 | 一句话价值 | 改动量 | 何时启用 |
|---|---|---|---|---|
| **P0 热备** | 备件 S3：烧与 S3#1 相同固件同配置，搁置待命 | 验收当天 S3#1 挂掉 → 10 分钟换板续命 | **零代码**，只烧录+验证 | 到手即做 |
| **P1 第五节点** | S3B：节点 id=4，入网成 5 节点 **20 链路** | 俯视质心定位从 12 条观测线升到 20 条，东侧补强 | 固件 4 处小改 + PC 表 3 处 | **主线 4 板联调通过后** |
| **P2 实验支线** | 呼吸检测实验机：不入网，独立固件 | 报告"CSI 能力上限"加分项素材 | 独立工程，零主线风险 | P0/P1 都不需要它时 |

**最优策略 = 依次履约，不并行占用**：到手先做 P0（热备是唯一能救验收的角色）；
主线联调通过、热备确认与主线互斥无冲突后，再评估是否升级 P1；
P2 只有在这块板确定空闲时才做，且用独立工程目录，绝不碰主线固件。

## 2. 容量盘点：第五节点入网的真实约束（已核实到行）

| 约束点 | 现状 | 5 节点需要 | 结论 |
|---|---|---|---|
| TX 侧本地源表 `CIS_CSI_SRC_MAX`（csi_tx_v1/main/cis_csi_rx.h:38） | **4** | 4（TX1/TX2/TX3/S3 + S3B 后恰好用满） | ✅ 无需改 |
| 协议 `observer_id` 字段（cis_protocol.h:168 等） | 1 字节 | 1 字节 | ✅ 宽度足够 |
| 节点 ID 上限 `CIS_NODE_SELF_ID`（ESP32_CIS_V1.0/main/Kconfig.projbuild:99） | `range 0 3` | `range 0 4` | 🔧 改 1 行 |
| S3 汇聚链路表 `CIS_LINK_MAX`（cis_protocol.h:88） | 12（4×3） | 20（5×4） | 🔧 改 1 行 |
| S3 发送方统计表 `s_node[4]`（cis_mesh.c:77，注释见 cis_mesh.h:73） | 4 槽 | 5 槽 | 🔧 改 1 行 |
| NVS 阈值 blob（cis_peer.c:343-344，`LINK_MAGIC="LNK1"` + `len != LINK_BLOB_SIZE` 校验） | 4+12×2=28B | 4+20×2=44B | ✅ **无需迁移**：长度不符自动拒绝、回落默认阈值，升级后重跑全量标定即可 |
| CMD_TRAIN 目标枚举（cis_mesh_train，S3→TX 单播） | 按 3 TX/按链路表 | 需覆盖 S3B | ⚠️ 实施时确认枚举来源 |
| PC `NODE_NAMES`（store.py:54） | 4 项 | +`4:"S3B"` | 🔧 1 行 |
| PC `MAC_DEVICE_MAP`（store.py） | 4 块板 | +S3B 真实 MAC | 🔧 到手后填 |
| PC `ZONE_ANCHORS`（ui_main.py） | 4 角 | +S3B 锚点 | 🔧 建议东侧中点 (0.85, 0.5) |
| PC `ui_smoke.py` 断言 | 12 卡片/曲线 | 20 | 🔧 同步更新 |

信道负载（估算）：源帧 100 Hz × 5 源 + FEAT_BUNDLE 10 Hz × 4 发方 ≈ 540 帧/s，
6M PHY 下单帧空口约 150~250 µs，合计空口占用 <15%；同频还有路由器 1003-k 背景。
**沿用既有判据**：`link list` 监控 seq 丢包率，>10% 则全网同步把
`CIS_MESH_SRC_RATE_HZ` 100→50（标定SOP 已有此规则，无需新规则）。

## 3. P0 热备：到手当天做完（零代码）

1. **读 MAC**：esptool chip_id 确认备板物理 MAC（**不要**沿用 S3#1 的 DC:DA:0C:1D:AE:10，
   备板 eFuse MAC 必然不同），记入本文档下方表格。
2. **烧录**：复用 ESP32_CIS_V1.0 现有构建产物（该工程当前 sdkconfig 即 S3 配置），
   `idf.py flash -p <备板COM>`。Kconfig `CIS_NODE_SELF_ID` 保持 3——热备的角色就是
   "S3#1 的替身"，烧同版同配置。
3. **验证**：上电看 banner `ESP32_CIS_V1.0 RX ready (M2)`、`link list` 能起、
   心跳帧 CRC 过（接 PC 用 `--auto-scan` 起一次上位机即可确认），然后断电搁置。
4. **换板预案**（写进验收 checklist）：S3#1 故障 → 拔下换备板上同支架同串口 →
   由于备份板节点身份（源 MAC 末字节 03）与 S3#1 一致，**其余 3 板与上位机零改动**；
   若配置了阈值持久化差异，重跑一次全量标定（`train` 全量 ≈ 每链路 15 s）。

> 注意 flash_rx.bat:14 的 `EXPECT_MAC` 物理板 MAC 硬守卫：给备板烧录走
> `idf.py flash` 手动流程即可（守卫本意是防 COM 混淆，人工确认备板 COM 后不构成障碍）；
> 若想统一走脚本，实施 P1 时给脚本加 `EXPECT_MAC` 参数化。

## 4. P1 第五节点 S3B：改动清单（主线联调通过后实施）

**S3B 跑什么**：与 TX1/TX3 同构 —— 用 csi_tx_v1 代码库 `set-target esp32s3`
（esp-radar 已在 S3 上验证可用），第二配置 `CIS_TX_NODE_ID=4`（build_tx3 已有
"同库双配置"先例，照抄该模式建 build_s3b）。S3B 的 4 条本地链路经 FEAT_BUNDLE
单播 S3，**不需要自己的串口线**，20 条链路全部仍从 S3 一个串口出。

固件（3 文件 + 1 处核实）：
1. `ESP32_CIS_V1.0/main/Kconfig.projbuild:99` — `range 0 3` → `range 0 4`（仅上限放宽，S3 自身仍配 3）。
2. `ESP32_CIS_V1.0/main/cis_protocol.h:88` — `CIS_LINK_MAX` 12 → 20。
3. `ESP32_CIS_V1.0/main/cis_mesh.c:77` — `s_node[4]` → `s_node[5]`（同步修 cis_mesh.h:73 注释 [0,4)→[0,5)）。
4. 核实 `cis_mesh_train` 的目标枚举：若按"已知源列表"迭代则 S3B 自动纳入；
   若有 3 TX 硬编码，扩到 4。
5. csi_tx_v1 需支持 esp32s3 target 的构建自检（`set-target esp32s3` 后全量编译一次，C3 工程同理不动）。

上位机（3 文件）：
6. `store.py:54` — `NODE_NAMES` 加 `4: "S3B"`；`MAC_DEVICE_MAP` 加 S3B 源 MAC（末字节 04）。
7. `ui_main.py` `ZONE_ANCHORS` — 加 `"04": (0.85, 0.5)`（东侧中点，补强东侧半场）；
   `PEER_COLORS` 确认 20 链路取模循环正常。
8. `ui_smoke.py` — 卡片/曲线断言 12 → 20（SimSource 需扩 5 节点对端，参考 peers 参数化）。

实施顺序：开分支 `s3b-fifth-node` → 固件 1-3 → S3+TX 全量重编译 → PC 6-8 →
smoke 过 → 真机烧 S3B + S3 → 全量标定（旧阈值 blob 因长度变化自动失效，属预期）→
`link list` 验 20 链路丢包率 → 合入主线。全程主线不受影响（分支隔离），
任何一步不过即弃分支，热备角色仍成立。

## 5. P2 呼吸检测实验支线（仅当板子空闲）

- **独立工程**（如 `lab_breath/`），不入 mesh、不设源 MAC 广播，单链路 1 发 1 收闭环。
- 技术路线（呼应报告展望章）：幅度域 → 相位域；CFO 校准后取相位序列，
  30 s 窗、0.1–0.3 Hz 带 FFT，峰即呼吸率；门控：谱峰显著性 + 谐波检查。
- 产出物定位：报告"能力上限讨论"一节的数据图 1~2 张 + 结论一段；
  **不做进主系统、不写进验收演示流程**。

## 6. 启用判据（决策树）

```
S3#2 到手
├─ 立即：P0 热备烧录+验证 + 登记 MAC（本文 §3）
├─ 主线 4 板联调通过？
│   ├─ 否 → S3#2 保持在热备位，什么也不动
│   └─ 是 → 现场定位效果东侧仍偏弱 / 想要 20 链路卖点？
│       ├─ 是 → 实施 P1（§4，分支隔离，一票否决即弃）
│       └─ 否 → 保持热备；若报告还需加分素材 → P2（§5）
└─ 验收当天 S3#1 故障 → 备板顶上（§3 换板预案）
```
