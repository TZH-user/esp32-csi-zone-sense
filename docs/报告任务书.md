## 4. 项目事实库（唯一可信来源）

### 4.1 系统概述

- 选题：发送节点分布各监测区，1 块 ESP32-S3 接收节点以 esp-radar 0.3.4 多 peer 按源 MAC 分发 CSI，逐链路运动/存在检测并经 UART 二进制协议上报；PC 端 Python 桌面监控（区域卡片+实时曲线+事件日志+CSV 记录/回放）。
- 组网：路由器模式（SSID 1003-k，STA 跟随 AP 信道），预留直收模式（固定信道混杂接收）兜底；RX 另开 SoftAP `CIS_RX-ae10` 兜底接入。
- 上行通道：串口 COM3 @ 2,000,000-8-N-1（主通道）；UDP 3333 可选；TCP 2323 无线 REPL。

### 4.2 硬件与身份（MAC 是唯一锚点，口号会漂移）

| 板 | 角色 | 芯片 | 物理MAC(esptool) | CSI源MAC(peer注册用) |
|---|---|---|---|---|
| ESP32-S3 16MB | RX | 双核LX7 | DC:DA:0C:1D:AE:10 | — |
| 经典#1 | TX1 | ESP32 | 8C:94:DF:A1:DD:D0 | 1a:00:00:00:00:00 |
| C3 | TX2 | RISC-V单核 | E4:B0:63:33:F0:40 | 1a:00:00:00:00:01 |
| 经典#2 | TX3(待恢复) | ESP32 | 8C:94:DF:A1:DA:4C | 烧前须改为 1a:00:00:00:00:02 |

### 4.3 协议与算法参数（写报告时逐条可引）

- 帧格式：`AA 55 | ver(0x01) | type | len(2B LE) | payload | crc16(2B LE)`；CRC16-CCITT-FALSE 覆盖 ver..payload，校验值 `crc16(b"123456789")==0x29B1`。
- 帧类型：0x01 心跳 11B (uptime/peer_count/free_heap/lost)；0x10 事件 15B (mac/name_id/state/score/rssi/ts，跳变即时+MOTION 2Hz)；0x11 特征 17B (mac/ts/mean/var/p2p/rssi，10Hz/peer)；0x20 日志；0x30 标定 12B (mac/train_s/threshold/noise)。
- 单位：mean/p2p=centi-amp（raw×100）、var/score/阈值=centi-var（raw²×100），u16 饱和。
- 检测：每 MAC 8 槽累加器（portMUX 临界区）；窗=10 包；FSM N=10 窗确认运动、M=25 窗回归静止、presence hold 10s；RSSI 跳变过滤 |ΔRSSI|>6dB 丢包+整窗作废；train 阈值 = max(噪声底×300%, 15)。
- PC 解析：0xAA55 搜索+CRC 准入+失步 1 字节重同步，容忍控制台日志交织；1MB 环形缓冲；三层丢帧计数（环/队列/固件心跳上报）。

### 4.5 局限与已知问题（"总结与展望"必须如实写）

1. 台架近距（<0.5m、RSSI 饱和）仅验证功能；正式指标须空间部署后重标定（挪动即作废）。
2. 检测的是"每链路扰动"，不能区分人数/身份——ESP32 CSI 物理局限（引文献）。
3. CSI 对环境敏感：换场地必须重 train；信道跟随 AP（当前实测信道 4）。
4. 联调期间 RX 出现两次未归因重启（疑 USB 供电跌落，未证实）——已列入部署排查项（独立供电对策）。
5. TX3（经典#2）芯片进不了下载模式待冷却恢复，三链路完整联调待其恢复后进行。
6. 检测算法仿真为宏观统计级标定（走动信号模型参数为假设、只锚定检出率/时延/噪声底），非信道冲击响应级建模；详见 `docs\算法仿真分析.md` §6。
