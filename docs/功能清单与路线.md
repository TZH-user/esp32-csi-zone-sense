# 功能清单与路线：当前硬件/架构能做什么（v1.0，2026-10-29）

> 口径：硬件 = 2×S3 + 2×经典 + 1×C3（收发一体，5 节点时 20 链路）；架构 = ESP-NOW mesh
> 汇聚 + 幅度域特征（mean/var/p2p，~10Hz/链路）+ 三态 FSM + 上位机区域图/CSV/回放。
> 难度分档：★☆☆ 纯上位机/配置，半天级；★★☆ 需真机数据调参，1~3 天；★★★ 需新算法
> 或改固件信号通路，不确定；✕ 现有硬件原理上做不到。
> 配套证据：M1~M4 日志（docs/logs/）、仿真六场景（docs/算法仿真分析.md）、A6 实测。

## A. 已验证 / 代码就绪（现场可演示）

**A1 运动检测**：每链路 100Hz 包级累积 → ~10Hz 窗方差（centi-var）→ 连续 N=10 窗超阈
判 MOTION。实测手臂挥动 var 200c→1000c+；阈值=标定噪声底×margin（默认 300%）。
**A2 存在检测**：MOTION 后连续 25 窗低于阈转 PRESENCE（人还在，只是不动），静息 10s
回 IDLE。三态迟滞防抖，事件只在迁移沿报。**A3 标定持久化**：15s train→阈值 NVS 存取，
软重启 4.9s 恢复（M4 实证）。
**A4 12 链路收发一体**：每板又发又收，observer×source=4×3，特征经 ESP-NOW 单播 S3
统一串口上报。编译、双端协议一致性、冒烟全过——**差真机 4 板联调**（当前待办）。
**A5 区域质心定位**：12 条链路中点按归一化响应加权质心，总响应≥门限才定位，静止保持
30s 淡出。逻辑与仿真过——**差真人走位验证**（质心分辨率预期 ±0.3m 量级，演示口径
"九宫格区域"而非坐标点）。

## B. 本次已接入/备好的功能（pc_dashboard/zone_features.py，自测全绿）

设计原则：**算法层纯逻辑、零 Qt 依赖、可吃 CSV 回放离线调通，UI 只加一行喂入**——
联调前不动主线行为，联调后按需点亮。

**B1 轨迹尾迹+走向（已接入 ZoneMap）**：确信定位点进 `TrajectoryAnalyzer`，
区域图画渐隐尾迹，标签追加走向（自西向东/自北向南…）。这是演示观感提升最大的一项：
人从门口走到座位，地图上留下一条带方向的轨迹线。

**B2 驻留检测（已备好）**：`DwellDetector(dwell_s=8)` 同区域连续停留且漂移小于门限
→ 一次 dwell 事件（每段只报一次，换区重置）。接入点：Dashboard 500ms 回路里把
`zone_map._pos` 喂入 + `pop_events()` 上事件表。演示口径："在贵重物品区停留超 8 秒告警"。

**B3 出入计数/再入场（已备好）**：人员消失 ≥8s 后重新定位 → reentry 事件（带时间/区域），
配合 B1 方向即"从东门进入"。接入点同 B2（`pop_events`）。

**B4 呼吸幅域预览（离线工具，已可日用）**：
```
python pc_dashboard/zone_features.py data/<会话>/cis_log.csv --observer S3 --mac 00
```
对单链路 var 序列重采样→去趋势→Hann 窗谱峰，输出谱峰频率/SNR/confident。
**用途**：人员静坐在链路 1~2m 处录 30s，confident=True 说明幅域就能看到呼吸（值得上
相位域 P2）；False 则坐实"必须换相位域"，两个结论对报告都有用。合成 0.25Hz 信号
端到端验证过（SNR 62.75），真机数据未测——这正是它作为"判据工具"的意义。

## C. 可行、未验证、需真机数据（★★☆）

**C1 疑似跌倒**：启发式 = 短时大扰动（全链路 var 齐飙）→ 位置迁移 → 新位置 PRESENCE
且长时间不动。`DwellDetector` + `TrajectoryAnalyzer` 事件序列已具备全部原料，
难在误报调参（坐下/蹲拾与跌倒在幅域里很像）。建议验收后做，报告可写"设计+局限"。
**C2 隔断感知**：2.4G 穿石膏板/木板只衰减 6~15dB，链路仍工作但方差响应变小——
用一张隔板放在既有链路上实测 var 响应衰减即可定量，半天实验。**C3 东侧补强**：
物理手段优先（东侧 TX 天线朝入场路径、板抬高 30-50cm），或 P1 的 S3B 放东侧中点
新增 4 条东半场链路（见支线方案）。**C4 幅域呼吸实测**：B4 工具 + 30s 静息录波，
一次实验出结论。

## D. 规划中（未动工）

**D1 告警联动**：事件迁移沿已集中在一处（`_on_record` EVENT 分支），加 Qt 信号→
声音/弹窗/写文件都是几行。**D2 遥测阈值**：远链路阈值目前须现场重标定，固件 3 参
命令已设计（挂账低优先级项）。**D3 拥塞自适应**：判据已有（>10% 丢包→全网同步
50Hz），自动化的价值低、风险高（需全网同步改），保持人工执行。

## E. 做不到 / 不值得（写进报告"局限"）

**E1 多人分离**：幅域特征是叠加标量，两人同场方差不可分离——ESP32 CSI 已知弱项，
演示口径主动说"单目标系统"。**E2 手势/近距精细动作**：近场饱和仿真定量复现
（mean_c>1500 检出塌缩，模型 1364c vs 实测 1224c），0.5m 内反而失效。**E3 相位域
呼吸在线版**：当前固件只用幅度，esp-radar 相位受 CFO 漂移污染需校准——按 P2 支线
独立工程推进，不承诺。**E4 802.11bf**：芯片不支持，写展望。
